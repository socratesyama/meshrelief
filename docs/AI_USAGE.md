# AI使用の説明

実装計画書 v2 §12.3では、AI使用について以下のような説明文が例示されていた。

> 「本作品の開発において、AI（Claude）を以下の目的で使用した:
> 1. プログラミング補助: React/TypeScriptコンポーネントの実装、CRDTエンジンのロジック構築
> 2. 設計検討: アーキテクチャ設計、データモデル設計、テストケース設計
> 3. ドキュメント作成: 技術ドキュメント、開発背景リサーチ
> ただし、アルゴリズムの設計判断（LWW競合解決ルール、ベクタークロック実装、QR差分同期プロトコル設計）は開発者が行い、AIは実装の補助として使用した。」

この文面をそのまま応募資料に使うと、実際の開発プロセスより人間の関与を
過大に、AIの関与を過小に表現することになると判断したため、ここでは
実際の経緯に即して書き直す。応募資料用の文面が必要な場合は、以下の
内容を踏まえて開発者自身の言葉で改めて作成することを推奨する。

## 実際の開発プロセス

1. **人間が実装計画書（本ドキュメントの元になった設計書）を作成した。**
   CRDTによる競合解決の方針（LWWを使うこと）、vectorClockによる差分
   同期という全体アーキテクチャ、QRコードによるオフライン転送という
   コンセプト、5つのデータパネル構成など、プロダクトとしての骨格は
   人間が事前に設計・記述していた。
2. **Claude（本AI）が、その設計書を1ファイル〜数ファイル単位のセッションに
   分けて実装した。** 設計書に明記された仕様（LWWの優先順位
   `lamport > updatedAt > nodeId` 、QRフレームのワイヤーフォーマット、
   IndexedDBスキーマ等）はその通りに実装したが、設計書に明記されて
   いない実装の詳細（例: `CRDTEntry.vectorClock` の正確な意味論、
   HMAC鍵のexport/import先クラス、テストで実際に使う合成エントリの
   組み立て方等）は、実装しながらClaudeが判断して埋めた。
3. **セッションを重ねる中で、人間が新しい要件（v3追加要件）を提示し、
   プロダクトの方向性を継続的に修正した。** 「常時待機・自動役割交代
   方式への変更」「同期ステーションモードの追加」「デフォルトの
   同期スコープ絞り込み」等は、実装が進む中で人間が新たに設計・
   指示した仕様であり、Claudeが自発的に提案したものではない。
4. **Claudeは、設計書の記述だけでは決められない実装判断（TypeScriptの
   型設計上の問題の発見と修正、モジュール間の依存方向の設計、
   コンポーネント分割等）を都度行い、それぞれを `DECISIONS.md` に
   理由付きで記録した。** 特に「設計書の意図と異なる可能性がある」
   判断には`要確認`/`要注意`のマークを付け、人間が後から検証・
   訂正できるようにした。実際、`DECISIONS.md`には人間から直接
   ファイルを修正された形跡についてClaude側から確認を求めた記録も
   残っている（session4冒頭）。
5. **テストコード・ドキュメント（本ファイルを含む）もClaudeが作成した。**
   ただし何をテストすべきか（§9.1/§9.2/§9.3の項目、v3要件のテスト
   ケース）は人間が指示した。

## まとめ

- **要件定義・全体設計・各セッションでの実装範囲の指示・レビューと
  訂正**: 人間が行った。
- **コード実装、実装レベルの詳細設計、その場で発見した設計書との
  矛盾の指摘と修正提案、テストコード、ドキュメント作成**: Claudeが
  行った（都度、判断根拠を`DECISIONS.md`に記録し、人間の確認を
  求める形で進めた）。
- 両者の役割分担・やり取りの詳細な記録は `DECISIONS.md` を参照。
  特に「設計書の記述とコードの対応表」の節には、Claudeが独自に行った
  判断とその理由が列挙されている。
